# 방문 연계: 게시본 규칙 vs 새 규칙 (규칙 및 건수 비교)

작성일: 2026-11-07
게시본: 이미 공개된 MIMIC-IV Extension 의 `image_occurrence.csv` (로컬에 마운트된 사본에서 읽음. 원본 객체와 바이트 단위로 같은지는 확인하지 않았다)
새 규칙의 상세 결정 기록: `visit_link_decision_20261107.md`

## 1. 게시본 규칙 (데이터에서 역추적한 것)

게시본을 만든 코드나 규칙 문서는 확인하지 못했다. 아래는 CSV와 CDM `visit_occurrence` 를 대조해 알아낸 동작이다. ECG(image_occurrence_id < 900,000,000, 796,617건)와 CXR(215,006건)의 규칙이 서로 다르다.

### 1.1 공통

- **날짜만 본다.** 이미지 날짜가 방문 `[visit_start_date, visit_end_date]` 에 들어가면 후보다. StudyTime/`ecg_time` 은 쓰지 않는다.
- **후보가 있으면 항상 연결, 없으면 NULL.** 후보가 없는데 연결된 건 0건, 후보가 있는데 연결 안 된 건 0건이다 (후보 없음: CXR 18,653건, ECG 161,152건).
- **입원/클리닉을 구분하지 않는다.** 연결된 방문 중 클리닉(38004207)은 CXR 35,079건, ECG 168,176건이고 나머지가 입원 계열이다.
- 후보가 1개면 그 방문이다 (후보 1개: CXR 188,120건, ECG 603,040건).
- 예외: 연결된 831,818건 중 **17건**은 게시본 방문이 날짜 후보에 없다. 원인은 확인하지 않았다.

### 1.2 후보가 2개 이상일 때 (40,658건 = CXR 8,233 + ECG 32,425)

| 모달리티 | 후보 시작일이 서로 다른 경우 | 후보 시작일이 같은 경우 (동점) |
|---|---|---|
| ECG | 가장 이른 시작일을 선택: **1,327 / 1,327건 (100%)** | 사실상 임의: 최저 id 15,475 / 31,098건 (49.8%), 최고 id 15,565건 (50.1%) |
| CXR | 가장 늦은 시작일을 선택: **310 / 316건 (98.1%)**, 가장 이른 시작일은 6건 | 최저 id를 선택: **7,784 / 7,917건 (98.3%)** |

- ECG는 "가장 이른 시작일, 동점은 정해진 기준 없음"에 해당한다. 동점이 전체의 96%(31,098건)라 전체로 보면 어떤 단순 규칙을 써도 52% 안팎만 맞는다. 이전 `fix_imaging_cdm_ids_v2.py` 코드는 시작일로 정렬한 뒤 첫 행을 취했고 id 동점 처리가 없었다. 위 관찰과 일치하지만, 게시본이 그 스크립트로 만들어졌다는 증거는 아니다.
- CXR는 "동점이면 최저 id"가 사실상 규칙으로 보인다. 시작일이 다른 경우는 316건뿐이라 "가장 늦은 시작일"은 표본이 작다.
- 입원/클리닉이 섞인 후보에서의 선택: CXR 7,660건 중 입원 3,875건, ECG 28,395건 중 입원 14,351건으로 반반이다. 입원을 우선하는 규칙은 아니다.

## 2. 새 규칙

방문 분류: 클리닉 = `visit_concept_id` 38004207, 입원 계열 = 262, 581385, 8870, 8883, 9201.

1. 입원 계열 방문 중 이미지 일시(StudyDate+StudyTime, ECG는 `ecg_time`)가 `[visit_start_datetime, visit_end_datetime]` 에 들어가는 방문 (`stay_datetime`). 여러 개면 시작 일시가 이른 방문, 그다음 낮은 id.
2. 못 찾으면 클리닉 방문 중 이미지 날짜가 `[visit_start_date, visit_end_date]` 에 들어가는 방문 (`clinic_date`). 여러 개면 시작 일시가 이른 방문, 그다음 낮은 id.
3. 둘 다 없으면 NULL.

## 3. 규칙 비교

| 항목 | 게시본 | 새 규칙 |
|---|---|---|
| 후보 조건 | 날짜가 방문 날짜 범위에 포함 | 입원은 **일시**가 방문 일시 범위에 포함, 클리닉은 날짜 범위에 포함 |
| 시각 사용 | 안 씀 | 입원 판정에 사용 |
| 입원/클리닉 | 구분 없음 | 입원 우선, 없으면 클리닉 |
| 날짜만 맞고 시각이 입원 구간 밖 | 그 입원에 연결 | 입원에 연결하지 않음 (같은 날 클리닉이 있으면 클리닉, 없으면 NULL) |
| 후보 여러 개 | ECG: 가장 이른 시작일, 동점은 임의 / CXR: 동점이면 최저 id (시작일이 다르면 가장 늦은 쪽) | 시작 일시가 가장 이른 방문, 동점이면 최저 id (결정적) |
| 후보 없음 | NULL | NULL |

## 4. 결과 건수 비교

두 쪽 모두 person이 있는 occurrence만 대상이다. 게시본 숫자는 CSV에서 직접 읽었다 (DB에 적재된 게시본 `image_occurrence` 와 건수가 같다). 새 규칙 숫자는 ECG는 ECG image_occurrence 결과 parquet 의 `ecg_time` 과 CDM 방문으로 pandas 계산, CXR는 CXR 전체 스키마의 `src_dicom_header` 에서 이미지 일시를 뽑아 SQL 임시 테이블에서 계산한 값이다. ETL/`lk_30` 을 실제로 돌린 결과가 아니다.

## 5. 해석

- 새 규칙은 게시본보다 연결이 조금 적다 (ECG −10,515건, CXR −779건). 모두 게시본이 날짜만 맞는 입원에 붙였지만 시각이 구간 밖이고 같은 날 클리닉도 없는 경우다. 새 규칙에서 새로 연결되는 건은 없다.
- "다른 방문"(ECG 16,423건, CXR 3,930건)에는 두 부류가 섞여 있다. (a) 게시본이 시각이 맞지 않는 입원에 붙였고 새 규칙은 같은 날 클리닉에 붙인 경우, (b) 후보가 여러 개일 때 게시본의 임의 선택과 새 규칙의 일시 기반 선택이 다른 경우. 이 두 부류의 건수 분해는 하지 않았다.
- ECG에서 게시본의 동점 선택이 임의이므로, 새 규칙과 달라지는 ECG 건 중 상당수는 게시본 쪽 선택에 근거가 없는 경우로 볼 수 있다. 다만 이것이 전부라고 확인한 것은 아니다.
- 시작 전 허용 오차를 두면 연결 상실을 일부 되돌릴 수 있지만, 이번에는 도입하지 않기로 했다 (2026-11-07 결정).

## 6. 한계

- 게시본 규칙은 역추적한 추정이다. 17건 예외와 CXR의 "시작일이 다르면 가장 늦은 쪽"(표본 316건)은 설명이 부족하다.
- 새 규칙 수치는 임시 계산이다. 전체 ETL(`run_etl.py`)과 `fix_imaging_cdm_ids_v2.py` 를 실제로 돌린 뒤 `validate.py` / `qa.compare_published` 출력과 대조해야 한다.
